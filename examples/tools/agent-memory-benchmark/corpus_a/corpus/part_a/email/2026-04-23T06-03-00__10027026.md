**Scheduled maintenance — GitLab runner pool**

Platform Eng Ops will be rotating the shared GitLab runner pool this weekend.
Expect CI pipelines on `gitlab.examplecorp.example` to queue longer than usual
during the window.

| Field | Value |
| --- | --- |
| Start | Saturday 2026-04-25, 03:00 UTC |
| End | Saturday 2026-04-25, 05:00 UTC (estimated) |
| Duration | ~2 hours |
| Affected systems | shared CI runners (tags `atlas-default`, `atlas-fast`, `beacon-default`) |
| Unaffected | dedicated runners (`atlas-gpu`, `compass-warehouse`); GitLab web UI; git push/pull |

**What to expect**

- New pipelines enqueued during the window will wait for a healthy runner
  before starting. They will not fail; they will simply be queued.
- Already-running jobs at 03:00 UTC will be allowed to complete; their host
  will be drained after.
- We do **not** plan any GitLab application restart, so MR pages, issues, and
  the API remain available throughout.

**Why**

We are picking up a new base image with the patched kernel from this week's
security bulletin, plus a 50% increase in `atlas-fast` capacity to absorb the
wave-ingest test load.
