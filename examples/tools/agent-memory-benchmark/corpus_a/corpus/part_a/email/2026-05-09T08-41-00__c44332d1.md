Got it. Looked at the logs you sent.

Root cause: the wiki group mutex is held by a stuck consolidate job. Ingest can't advance the watermark because every wave needs the mutex to write self-model pages, and the consolidate worker has been holding it since 04:12 UTC two days ago. The worker thread is alive but blocked on a provider call that never returned — no timeout on that path. That's the bug.

Immediate unblock for the customer:
1. `atlas stop`, then `atlas start --daemon`. The mutex is in-memory; restart frees it.
2. The watermark will advance on the next wave. They should see progress within a few minutes.

Real fix is mine: add a timeout + retry to the consolidate-side provider call so a single hung request can't wedge the mutex. I'll file an MR today.

Forward this to their on-call. Sorry it bit them on a flagship instance — this is exactly the kind of failure we need better signal on. I'll also add a metric for "mutex held > N minutes" so MetricsWatch alerts before a customer notices.
