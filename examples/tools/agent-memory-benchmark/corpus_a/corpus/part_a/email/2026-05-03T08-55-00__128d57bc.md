All,

Sending early so teams can plan: the auth-scope policy is changing next sprint. Short version — we're tightening the default scope granted to internal service tokens, and the broader `service:*` wildcard goes away.

Why now: a recent audit surfaced too many services holding wider scopes than they actually exercise. The new policy aligns issued scopes with measured call patterns over the last 60 days.

What changes for Atlas:
- Tokens minted after May 18 will be issued with the narrower scope set documented at https://wiki.examplecorp.example/security/auth-scope-2026-q2.
- Existing tokens keep working until their natural rotation; no emergency rotation required.
- The agent runtime's outbound calls were already in scope; you should not see runtime breakage.
- Anything touching the wiki write path or the raw store will need an explicit scope grant — Dimitri and I prepared a one-pager.

Action items for the team:

- One owner per project to validate the scope diff in staging by May 14.
- File any exceptions through the standard review queue with `auth-scope-2026` in the title.
