**P1 — `cost_report` prints per-item prompt previews including page bodies**

`src/atlas/cli/cost_report.py::_format_item_row` prints the first 200 characters of each prompt to help debugging. For waves that include wiki page bodies (which is most of them), this surfaces user content into stdout of a CLI that an operator might pipe to a shared paste service. Either drop the preview entirely, or gate it behind a `--verbose` flag that also prints a "this output may contain user content" banner.

```python
def _format_item_row(item: ItemCost, *, show_prompt: bool = False) -> str:
    base = f"{item.id:<24} {item.input_tokens:>8} {item.output_tokens:>8} ${item.cost_usd:>6.4f}"
    if show_prompt:
        base += f"  prompt={item.prompt_preview[:80]!r}"
    return base
```

<details><summary>Prompt To Fix With AI</summary>

> In `src/atlas/cli/cost_report.py`, remove the unconditional prompt preview from `_format_item_row`. Add a `--show-prompt-preview` flag that is False by default; when True, print a one-line warning to stderr that the output may include user content and reduce the preview length to 80 chars. Update `tests/cli/test_cost_report.py` to assert the default output contains no prompt content, and add a separate test for the verbose path.

</details>

**P1 — Runbook cost formula assumes prefix-cache and wiki-cache are multiplicative; they aren't**

The runbook says "expected cost = base_cost × (1 − prefix_hit_rate) × (1 − wiki_hit_rate)". That treats the two caches as if a miss in one is independent of a miss in the other. In practice, a wiki cache miss forces a longer prompt prefix (because the new page content has to be re-injected), which lowers the *effective* prefix cache hit rate for that item. The two caches are correlated, not independent. Rewrite the formula or — easier — drop the formula and just show the measured per-wave cost.

```yaml
# replace formula section with measured-cost table
columns:
  - wave_id
  - items_processed
  - total_cost_usd
  - wiki_cache_hit_rate
  - prefix_cache_hit_rate
note: "Compute savings by comparing waves before/after a change; do not predict from rates."
```

<details><summary>Prompt To Fix With AI</summary>

> In `docs/runbooks/ingest-cost-rollup.md`, remove the "expected cost" formula section and replace it with a table of measured per-wave columns (`wave_id`, `items_processed`, `total_cost_usd`, `wiki_cache_hit_rate`, `prefix_cache_hit_rate`). Add a note explaining the two cache hit rates are correlated (a wiki miss extends the prompt prefix and reduces effective prefix-cache hit) so operators should compare measured costs across waves rather than predicting from rates.

</details>
