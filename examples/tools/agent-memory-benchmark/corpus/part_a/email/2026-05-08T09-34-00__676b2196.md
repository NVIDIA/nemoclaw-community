Team,

The security review queue has gotten long enough that I'm asking everyone — Atlas, Beacon, Compass, Helix — to file reviews earlier than you've been used to. The 1-week buffer we used to operate on is no longer realistic.

What's changing:
- Default SLA is now 2 weeks from filing to first review pass. Plan accordingly.
- Anything touching auth, token handling, external partner endpoints, or user-data egress should be filed before the implementation MR opens, not after.
- "Quick check" requests still exist but only for changes strictly limited to internal infra (CI config, lint rules, telemetry).

What you can do to make it move faster:
- Use the structured template at https://wiki.example-co.com/security/review-template — reviews skip the template-less filings to the back of the queue.
- One review per MR set. If you have three related MRs, link them in one filing rather than splitting.
- Attach the threat-model section even if it's "no change from prior" — saying so explicitly saves a round-trip.

A note specifically for Atlas: the auth-scope changes Priya circulated last week will land May 18. Any Atlas MR that touches token mint paths after that date needs a fresh review even if I reviewed an earlier version — the policy is a behavior change, not just a config change.

If you have something already in flight, please ping me directly with the link and I'll triage. Otherwise, file via the standard form and budget the two weeks.

Thanks for working with us on this — the queue is long because the bar is rising, which is a good problem.

Dimitri
