#### P2 — Backoff parameters are hard-coded and shared with `ingest_backfill`

`MAX_RETRIES = 5` and `BACKOFF_BASE = 0.05` are module-level constants in `orchestrator.py`. The realtime wave path is fine with that — total worst-case backoff is 50+100+200+400+800 ms ≈ 1.5s. But `ingest_backfill` shares the same orchestrator instance and runs against a much busier writer (the catch-up cron writes thousands of rows per minute). Under that workload the lock-held window is longer and 1.5s of total retry budget is not enough; we'll see spurious `OperationalError` propagated up to the agent-job runner and counted as a job failure.

Either make backoff config injectable per caller, or have the backfill caller wrap dispatch in its own retry envelope.

```python
# src/atlas/ingest/orchestrator.py
@dataclass
class CommitRetryPolicy:
    max_attempts: int = 5
    base_delay: float = 0.05

class Orchestrator:
    def __init__(self, ..., retry: CommitRetryPolicy = CommitRetryPolicy()):
        self._retry = retry
```
