Found it.

> 0.91 -> 0.42. half the prompts are missing the cache

I ran the diff. The culprit is `src/atlas/prompts/ingest_system.md`. Two commits ago I added a `{{current_date}}` template var into the header for some debugging breadcrumb logic — meant to remove it before merging. Didn't. The date changes every UTC midnight, so every prompt rendered after a date rollover gets a unique prefix, busting the cache.

Why it shows as ~50% miss and not ~100%: backfill items render with `current_date=item.ingested_at` (a stable past date), so those still hit. Live ingest fills the misses.

Fix is a one-liner — drop the template var, push the breadcrumb to the *user* portion of the prompt where cache doesn't care. Doing it now, will land tonight.

For the post-mortem doc:

(a) We don't have a guard against accidental prefix-cache invalidation. I'm going to add a test that renders the system prompt twice on different mock dates and asserts byte-equality. Cheap and would have caught this.
(b) We should also surface `prompt_cache_hit_ratio` on the same dashboard as ingest cost, with a threshold alert (<0.7?). Right now you have to know to go look for it.

I'll write up the post-mortem tomorrow. Want to loop Morgan in or keep it engineer-level?
