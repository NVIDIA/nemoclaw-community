#### P1 — Orchestrator retry path doesn't distinguish lock contention from other `OperationalError`s

`Orchestrator._commit_all` now catches `sqlite3.OperationalError` and retries up to 5 times with exponential backoff. But SQLite raises `OperationalError` for both `database is locked` (transient — retry is correct) and `disk I/O error` / `database disk image is malformed` (terminal — retry is wrong, and the backoff just delays the failure surfacing). Filter on `"locked" in str(err)` (or use `e.sqlite_errorcode == SQLITE_BUSY` once SQLite 3.41+ is required) before retrying.

```python
# src/atlas/ingest/orchestrator.py
def _is_lock_error(err: sqlite3.OperationalError) -> bool:
    return "locked" in str(err).lower() or "busy" in str(err).lower()

for attempt in range(MAX_RETRIES):
    try:
        return self._do_commit(staged)
    except sqlite3.OperationalError as e:
        if not _is_lock_error(e) or attempt == MAX_RETRIES - 1:
            raise
        await asyncio.sleep(BACKOFF_BASE * (2 ** attempt))
```
