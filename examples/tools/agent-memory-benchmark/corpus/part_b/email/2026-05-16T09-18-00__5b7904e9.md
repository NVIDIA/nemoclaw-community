**[P1] CLI bypasses the cached config**

`src/atlas/cli/wiki_cmds.py` builds `AtlasConfig.from_file(default_config_path())` inside each subcommand. The click root command already attaches an `AtlasConfig` to `ctx.obj`. Reading it twice means the cache built in the root command is discarded and every CLI invocation does another full resolve. Worse, if the user passes `--config <path>` to override the location, the override is honored by the root command but the subcommands silently read the default again.

```python
# src/atlas/cli/wiki_cmds.py
@wiki.command("path")
@click.pass_context
def wiki_path(ctx: click.Context) -> None:
    cfg: AtlasConfig = ctx.obj["config"]
    click.echo(cfg.wiki_root)
```

**[P2] `expanduser()` runs before the missing-key guard**

`resolve_wiki_root` currently does `Path(root).expanduser().resolve()` where `root` is the raw value from the config. If `root` is the empty string (e.g. `wiki_root = ""` in atlas.toml), `Path("").expanduser()` returns `PosixPath('.')`, which then resolves to the current working directory. The wiki would silently start writing into the daemon's cwd. Treat empty-string as missing.

```python
def resolve_wiki_root(cfg: AtlasConfig) -> Path:
    root = cfg.get("wiki_root")
    if not root:  # catches None and ""
        raise ConfigError.from_code(WIKI_ROOT_UNSET)
    return Path(root).expanduser().resolve()
```

<details>
<summary>Prompt To Fix With AI</summary>

Change the falsy check in `resolve_wiki_root` from `if root is None` to `if not root` so that empty-string values trigger the same `ConfigError`. Add a parametrized test that exercises both `None` and `""` and asserts the same error code is raised.

</details>
