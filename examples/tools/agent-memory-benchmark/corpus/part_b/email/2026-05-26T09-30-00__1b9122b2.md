**P2 — `rate()` recommendation is wrong for a per-wave reset gauge**

The runbook says "Use `rate()` over 5m for live dashboards" for the cost column, but the cost gauge is reset at each wave commit, not a monotonic counter. `rate()` on a gauge that resets will compute negative rates at the reset instant and the dashboard will show spikes that don't correspond to real activity. The right primitive here is `sum_over_time` (if you want cumulative cost across waves in a window) or just the gauge value itself for a per-wave dashboard.

```promql
# correct: cumulative cost across waves in a 1h window
sum_over_time(atlas_ingest_wave_cost_usd_total[1h])

# correct: most recent wave's cost
atlas_ingest_wave_cost_usd_total
```
