**P2 — Cache stats snapshot is read under lock but consumed outside it; can show inconsistent hit-rate pair**

`WikiCache.stats()` returns `(hits, misses)` correctly under the lock. The metric exporter in `src/atlas/services/metrics_service.py` does:

```python
hits, misses = cache.stats()
total = hits + misses
gauge_hit_rate.set(hits / total if total else 0.0)
gauge_total_reads.set(total)
```

This is fine for the gauge values themselves, but if `cache.reset_stats()` runs between calls (during the per-wave metric flush), the `total` you computed and the `total` the gauge ultimately publishes can diverge. Cleaner: return a single immutable `CacheStats` dataclass from `stats()` and compute `hit_rate` inside it.

```python
@dataclass(frozen=True, slots=True)
class CacheStats:
    hits: int
    misses: int

    @property
    def total(self) -> int:
        return self.hits + self.misses

    @property
    def hit_rate(self) -> float:
        return self.hits / self.total if self.total else 0.0
```
