Thanks Alex,

Going with distribution-based. Here's the plan:

1. Metric is symmetric KL between predicted-probability histogram and label-probability histogram, computed per priority class, averaged.
2. The single-number rollup is `1 - normalized_kl` rescaled to 0–100, where 100 is identical distributions and the random-baseline scores ~50. I picked rescaling over raw KL because reviewers will pattern-match on "higher is better, 100 is the ceiling."
3. The eval README will lead with a worked example: "for last week's MR #412, the score moved from 78 to 82, meaning the priority-3 over-confidence problem improved by roughly this much."

Anya is reusing the same metric on Beacon's golden set with their own labels, so we get free cross-product comparison.

- Once the metric is wired into the pipeline I'll send you the first week of MR-by-MR scores so we can sanity-check whether the trend matches your intuition.
- If you want to declare a regression threshold (e.g. "block MR if score drops > N"), I'd rather encode that once than relitigate it per MR.
