The runbook explains where the numbers come from and how to query them, but doesn't say that the per-wave gauges are written at wave-commit time (so the freshest values are at most one wave behind the running pipeline). An operator looking at a dashboard and seeing "no change for 10 minutes" might think the pipeline is stuck, when in reality the next wave just hasn't committed yet. Add a one-paragraph "Freshness" note.

```markdown
## Freshness

The per-wave gauges are written when each wave commits, not continuously
during the wave. Typical wave duration is 1–3 minutes under normal load,
so dashboards should expect updates at roughly that cadence. If the
`atlas_ingest_wave_cost_usd_total` gauge has not changed for >5 minutes,
check whether the ingest pipeline is processing — gauges do not refresh
on empty waves.
```
