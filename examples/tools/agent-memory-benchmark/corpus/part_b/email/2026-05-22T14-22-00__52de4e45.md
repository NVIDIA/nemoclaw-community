**P2 — Failed wiki read can still leave a partial entry in the cache (carryover from pass 1)**

This is the same finding as before — the `put_from_loader` path is unchanged in the latest commits, so an empty result from a transient `WikiNotFound` will still be cached as "empty page" instead of triggering a retry. Mentioning again because the new holder assertion in `invalidate_all` makes the symptom worse: a failed loader during the consolidate phase will leave the cache populated, the session will exit normally, and the next session in the same wave will read stale empty data instead of refetching. Recommend wiring `CacheLoadResult.status` end-to-end as suggested previously.

```python
@dataclass(frozen=True)
class CacheLoadResult:
    pages: tuple[PageRef, ...]
    status: Literal["ok", "empty", "failed"]

def put_from_loader(self, page_id: str, result: CacheLoadResult) -> None:
    if result.status == "failed":
        return  # never cache failed loads
    self._entries[page_id] = _Entry(pages=result.pages, status=result.status)
```
