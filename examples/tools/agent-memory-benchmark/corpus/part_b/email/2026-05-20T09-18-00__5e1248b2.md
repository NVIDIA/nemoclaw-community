**[P1] Invalidator callback list leaks dead builders**

`AtlasConfig.register_invalidator` appends to `self._invalidators` without ever removing entries. The wave service constructs a new `PromptBuilder` per session; each one registers a callback that holds `self` via closure. Over a long-running daemon the list grows monotonically and `cfg.reload()` invokes callbacks on dead instances. Use a `WeakMethod` or expose `unregister`.

```python
# src/atlas/config/__init__.py
import weakref

def register_invalidator(self, cb: Callable[[], None]) -> None:
    self._invalidators.append(weakref.WeakMethod(cb))

def reload(self) -> None:
    ...
    self._invalidators = [
        ref for ref in self._invalidators if (live := ref()) is not None and (live(), True)[1]
    ]
```

<details>
<summary>Prompt To Fix With AI</summary>

Update `AtlasConfig.register_invalidator` to store `weakref.WeakMethod` references. In `reload()`, walk the invalidator list, drop dead refs, and invoke live ones. Add a unit test that creates a `PromptBuilder`, drops the only strong reference, garbage-collects, then calls `cfg.reload()` and asserts the invalidator list is empty afterward.

</details>

**[P2] Top-K hardcoded; should be configurable**

`_tokens_for_index(section, top_k=256)` bakes in the default at the call site. Other ingest knobs (`batch_size`, `wave_concurrency`, `prompt_layout`) all live under `[ingest]` in `atlas.toml`. The selector cap should be one of them so an operator can dial recall vs. memory without a code change.

```toml
# atlas.toml
[ingest]
context_selector_top_k = 256
```

Document the knob in `docs/design/ingest_pipeline.md` next to the top-K paragraph added in the previous commit. Update `tests/ingest/test_context_selector.py` to parametrize at least one test over `top_k in (64, 256, 1024)`.
