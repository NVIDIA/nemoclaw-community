NVIDIA recipes

Reusable agent recipes authored or maintained by NVIDIA. Placement does not state a support or maturity level.

NVIDIA recipe

Developer Community Chief of Staff

Synthesizes Slack, Outlook, GitHub, and mirrored community signals into operating briefs, gaps, priorities, and follow-up recommendations.

Requires
Docker, OpenShell 0.0.85, an inference key, and Slack or Outlook credentials.
External access
Inference and the selected messaging channel; exact read-only GitHub repositories; optional GitLab and Tavily; host-mirrored forum and history data.
Boundary
Personal, single-host managed virtual machine recipe; not a Kubernetes deployment. Repository support is best-effort.
Open setup and verification guide for Developer Community Chief of Staff

NVIDIA recipe

Kubernetes GPU Autoscaling

Runs a CPU-only NemoClaw/OpenClaw sandbox through OpenShell on Kubernetes and autoscales authenticated, GPU-backed Ollama inference pods from DCGM utilization.

Requires
Kubernetes 1.25+ with kubectl, Helm 3, allocatable NVIDIA GPUs, GPU Operator/DCGM, and Metrics Server. The OpenShell path also needs Docker Buildx, a pullable registry, a version-matched OpenShell command-line interface (CLI), Agent Sandbox custom resource definitions, and OpenID Connect or the documented unauthenticated evaluation exception.
External access
Cluster-local authenticated inference, registry and model downloads, and TLS through Envoy by default.
Boundary
Experimental. Validated on single-node MicroK8s on Brev AWS with four L40S GPUs; four GPUs is not a hard limit.
Open setup and verification guide for Kubernetes GPU Autoscaling

NVIDIA recipe

Memory-Driven Chief of Staff

Keeps a locally-authoritative, revisable record per inbound email and Slack message, re-judged on a schedule and re-ranked under fixed caps, without writing back to the source.

Requires
Python 3.10+ for offline fixtures; Linux, Hermes 0.19+, and a model credential for scheduled operation.
External access
Fixtures use no network. Scheduled jobs reach only the configured inference provider. Email and Slack connectors are not included yet.
Boundary
Designed for one person’s work stream. It is a recipe, not a product, and has no support commitment.
Open setup and verification guide for Memory-Driven Chief of Staff

NVIDIA recipe

PR Review Advisor

Reviews exact pull request heads with a constrained Hermes workflow, produces attested artifacts, and publishes only through a separate maintainer action.

Requires
Linux, Docker, OpenShell 0.0.85, Git, Node.js 22.19+, Python 3, curl, and an inference provider. The workflow also needs GitHub.com and a dedicated self-hosted runner.
External access
The inference endpoint receives repository and pull request context. GitHub credentials are removed before model work; publication is a separate host action.
Boundary
Hermes-only educational blueprint, not a hosted service. Version 0.1 does not support GitHub Enterprise Server.

Partner recipe · BlueTier

x402 Payment Gate

Releases an agent's x402 payments through a maker/checker boundary: the sandboxed agent can only submit payment intents, and a host-side gate outside the sandbox re-screens each one with pre-signature GO/HOLD/STOP verdicts (counterparty reputation, price anomaly, OFAC sanctions) before anything is signed or settled.

Requires
Python 3 for the host boundary, Docker and OpenShell for sandbox verification, and access to the Blackwall verdict service.
External access
Only the payment claim is sent to Blackwall. The sandbox has neither a signing key nor a payment-rail route.
Boundary
BlueTier-supported boundary demonstration, not an interactive Hermes runtime. It uses no real money; the public verdict service has no service-level agreement.
Open setup and verification guide for x402 Payment Gate

Partner recipe · HPE

Retail Assistant

Provides role-aware retail operations through Telegram, FastAPI, PostgreSQL, Docker Compose, and Helm.

Requires
A Telegram bot token and user IDs, a tool-calling large language model, and either Docker or Kubernetes with Helm. Docker Compose requires access to /var/run/docker.sock.
External access
Telegram and the inference endpoint. FastAPI and PostgreSQL remain deployment components.
Boundary
HPE-contributed demonstration presented as-is. Telegram-ID identity mapping is a demonstration workaround; deployments should use an external identity provider.
Open setup and verification guide for Retail Assistant

Partner recipe · Shrike Security

Shrike Security Action Governance

Governs agent tool calls with a before_tool_call plugin that returns allow / warn / require_approval / block from Shrike's enforce plane, with host-side secret handling and scoped egress to Shrike.

Requires
NemoClaw/OpenShell, an inference provider, a Shrike API key, Node.js/npm, and curl.
External access
Tool-call action content is sent to Shrike over TLS on two scoped POST routes. Without a key, nothing is sent and default behavior blocks fail-closed.
Boundary
Provided as-is and outside NVIDIA support. It is in-sandbox defense-in-depth, not an independent security boundary; runtime installation is best-effort.
Open setup and verification guide for Shrike Security Action Governance

Community recipes

Reusable agent recipes contributed independently without formal organizational provenance.

Community recipe

Deep Research Worker

Queues long-running research tasks from one sandbox to a host-side DeepAgents worker, with a narrow worker-only sandbox policy and optional read-only host-side search integrations.

Requires
Docker Compose, Python 3.10+ for local checks, an existing dedicated sandbox, and an OpenAI-compatible inference endpoint.
External access
The sandbox reaches only the host worker on port 9050. The worker reaches inference and optional host-side search helpers.
Boundary
Independent community contribution, not NemoClaw core. It has no NVIDIA support or readiness guarantee; operators own production hardening.
Open setup and verification guide for Deep Research Worker

NVIDIA field demo

DGX Station Blender and Omniverse

Controls visible Blender on DGX Station, renders with OVRTX, and runs native OVPhysX simulations.

Requires
DGX Station with Ubuntu 24.04 ARM64, GB300, an RTX-capable GPU, Blender 5.1.x, OVRTX/OVPhysX, local Nemotron 3 Ultra, NemoClaw/OpenShell, Docker/NVIDIA Container Toolkit, and a Hugging Face read token.
External access
Local inference and the host Blender Model Context Protocol bridge, with public release and model downloads during setup.
Boundary
Validated on the documented DGX Station, GB300, and RTX PRO 6000 configuration. It is an additive upstream extension with temporary compatibility patches.
Open setup and verification guide for DGX Station Blender and Omniverse
